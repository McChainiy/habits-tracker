# Архитектура

## Продуктовый контур

MVP — локальное iOS-приложение. Пользователь создаёт один месячный челлендж, добавляет от 1 до 5 привычек, задаёт наказание для каждой привычки и ежедневно отмечает статус.

На первом этапе приложение не требует регистрации, сервера и внешней синхронизации.

## Основные сущности

- `User` — владелец данных и будущая единица авторизации/синхронизации.
- `Challenge` — месячный челлендж: месяц, год, даты начала и конца, статус.
- `Habit` — привычка внутри челленджа: название, описание, наказание, цвет, порядок.
- `HabitEntry` — отметка привычки за конкретную дату: выполнено, не выполнено или пропущено.
- `updated_at` и `deleted_at` используются для timestamp-based синхронизации и soft delete.

## iOS

Локальный MVP строится на SwiftUI и SwiftData:

- `RootView` выбирает активный челлендж или показывает создание месяца.
- `SetupChallengeView` создаёт месяц и привычки.
- `MonthDashboardView` показывает календарь, привычки и ежедневную отметку.
- SwiftData хранит `Challenge`, `Habit` и `HabitEntry` локально.

## Backend

Backend создаётся как готовый каркас для следующего этапа:

- FastAPI обслуживает REST API.
- SQLAlchemy async работает с PostgreSQL.
- Alembic управляет миграциями.
- API начинается с `health` и базовых операций по челленджам.
- Docker Compose поднимает API и PostgreSQL для локальной разработки.

## Синхронизация

Синхронизация строится по временным меткам:

- клиент хранит локальные изменения в SwiftData;
- `GET /api/v1/sync/changes?since=...` возвращает изменения пользователя после указанного времени;
- `POST /api/v1/sync/push` принимает изменённые локальные сущности и сохраняет их на сервере;
- сервер выставляет свой `updated_at`, возвращает `server_timestamp`, а клиент сохраняет его как точку следующей синхронизации;
- удаления передаются через `deleted_at`, физическое удаление записей не используется в синхронизируемом контуре.

До подключения полноценной авторизации backend использует заголовок `X-User-Id`. Позже этот слой должен быть заменён на Sign in with Apple или другой auth provider.

## Принятые ограничения MVP

- Только один активный месячный челлендж в интерфейсе.
- До пяти привычек на челлендж.
- Наказание хранится текстом внутри привычки.
- Приложение не проверяет исполнение наказания автоматически.
- Автоматические блокировки и пуши выносятся в следующие этапы.
